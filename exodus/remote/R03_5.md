# R03.5: native ARM64 diagnostic admission

Tracks #89, stacked on #137. This is an NRO build and local read-only diagnostic, not a native remote server yet. Use devkitA64/libnx and Switch OpenSSL portlibs. Build: make -C exodus/remote. OpenSSL 3.x APIs are required; a missing package or incompatible port is a build failure, not a reason to weaken TLS.

On a Switch, start the NRO locally and press A. Record exact firmware, execution context, diagnostic output and artifact SHA256. Press Plus to exit. Expected: current-process memory, battery, and SD capacity or explicit unavailable results, monotonic clock, TLS 1.3 context/RNG, and deny-by-default gate. This tests neither a full TLS handshake nor TCP networking. No socket initialization, listener, certificate provisioning, remote grants, package install, NAND writes or Nintendo online access.

The native CI job is intended to verify cross-compilation, AArch64 ELF and NRO structure, and publish a test artifact. Native execution and policy integration remain separate gates. Do not enable a device listener until those are reviewed. The local diagnostics are not remote capability admission. No physical device test has been executed for this change.
