# R03.5 / R03.6: native ARM64 diagnostic admission

Tracks #89; stacked on #137. Local read-only NRO, not a native remote server.
The first CI run 45505598279 failed before compilation: switch-openssl is not
available from the configured devkitPro repositories. The official switch-mbedtls
recipe currently packages 2.28.10, which is not a TLS 1.3 implementation.
Use that available package strictly for native entropy/version diagnostics.
The host OpenSSL 3.x TLS 1.3 transport stays unchanged. No TLS 1.2 fallback.
Native remote transport remains blocked until a reviewed TLS 1.3 backend is
built and verified, including mutual authentication, pinning and revocation.

Build: make -C exodus/remote. CI uses a recorded devkitA64 image digest;
package versions are logged. On the console launch the NRO locally, press A,
record firmware, context, diagnostics and artifact SHA256; Plus exits.
Expected: process memory, battery and SD capacity or explicit unavailable,
monotonic clock, Mbed TLS entropy result, TLS 1.3 configuration report and
deny-by-default dispatch. A successful entropy test does not prove TLS security.
A negative TLS 1.3 report blocks transport but does not invalidate local telemetry.

No listener, socket initialization, remote grants, credential provisioning,
NAND writes or Nintendo online access. Native CI and physical device validation
are separate gates. No physical test yet. Never expose the diagnostic as a
network service.
