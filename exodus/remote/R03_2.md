# R03.2: authenticated EXR/1 session integration

Tracks #89; stacked on #95. Binds a verified TLS 1.3 SSL object to one EXR/1 connection and a monotonic expiry. Each step rechecks the live local ACL, owner opt-in and session expiry before doing one bounded read/write attempt. No pending reply is sent after a detected ACL change or provider-mask change; abort the transport on EXS_CLOSE, without flushing or TLS shutdown. Bytes previously accepted by the transport cannot be recalled. The provider is a trusted synchronous implementation; the caller serializes its state, including policy updates. No remote shell, listener, certificate provisioning or automatic pairing is enabled.

Run: sh test_remote_session.sh from exodus/remote. Local GCC 14.2 and OpenSSL 3.5.7 with ASan/UBSan: passed, using actual TLS handshakes over BIO pairs and a mock provider. Base gate/wire/TLS headers matched repository Git blob hashes. Tested successful status request, denied battery access, filtered discovery, revocation with pending reply, provider availability change and expiry. No native SDK, hardware, TCP listener or forced socket backpressure tests yet.

Next: owner-opt-in foreground loopback/TCP server with nonblocking sockets, connection and handshake deadlines, event-loop scheduling and local stop. Caller must bound provider latency and service/connection resources, recheck policy at idle ticks, handle SSL WANT states correctly, and abort immediately on close. Integrate the reviewed shared capability policy before enabling any real device listener. No Nintendo online services.
