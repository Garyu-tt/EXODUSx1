# R03.7 isolated Mbed TLS 3.6.8 port experiment

Tracks #89; stacked on #138. Host OpenSSL reference stays unchanged.
Temporary cross-build experiment, not a production transport. 3.6.8 includes
November 2026 security fixes; 3.6 LTS ends March 2027, so evaluate maintained
4.1 LTS or another maintained backend before production. Archive SHA-256
pinned using OpenWrt 3.6.8 package recipe:
https://github.com/openwrt/openwrt/blob/main/package/libs/mbedtls/Makefile
https://mbed-tls.readthedocs.io/en/latest/security-advisories/mbedtls-security-advisory-2026-11-tls13-transform-resource-leak/

Build private static libraries; do not replace SDK packages. CSRNG IPC is
the hardware entropy hook; errors clear the buffer and fail closed.
X.509 date checks remain compiled. Local NRO tests CSRNG, PSA, entropy and
TLS 1.3 configuration. No socket, certificate, handshake or remote operation.
Library may compile other protocol versions; diagnostic selects TLS 1.3 only.
Before transport admission prove TLS 1.3-only negotiation, trusted clock,
mTLS, pinning, no resumption/early data, revocation, bounded I/O and local
opt-in. Cross-build and physical execution both unverified at submission.

R03.9: the isolated configuration now removes TLS session tickets, cache,
context serialization, TLS 1.3 PSK modes and persistent PSA key storage.
The diagnostic rejects unexpected flags at compile time and requires date
validation and retained peer certificates. These are build configuration
checks, not evidence of a successful TLS handshake. The previous CI failure
was Git safe.directory; its narrowly scoped fix is in the workflow.
