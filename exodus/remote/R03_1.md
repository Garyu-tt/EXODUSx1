# EXODUS Remote R03.1: mTLS reference gate

Tracks #89; stacked on #94. OpenSSL 3.x host reference, TLS 1.3 only, explicit CA, mandatory client certificate, exact SHA-256 certificate fingerprint and local grant table (max 64). Duplicate pins denied. No session resumption or early data. No custom cryptography.

Run from exodus/remote: sh test_remote_tls.sh. Local GCC 14.2 strict C11 plus ASan/UBSan passed using OpenSSL 3.x and real in-memory TLS handshakes, including invalid CA, absent certificate, unpaired certificate, duplicate ACL entries and revoked grants. Test keys are temporary and never production credentials.

No socket listener, pairing UI, ACL persistence, EXR/1 integration, hardware validation or native OpenSSL build yet. A trusted local owner must provision certificates/pins and protect private keys, use verified wall-clock for certificate validation, verify server identity on client, and explicitly confirm pairing. Refresh current ACL and intersect granted operations with EXR known and reviewed mask before each dispatch and reply. Close on revocation; apply monotonic expiry, connection limits, handshake/read/write deadlines and local stop. Certificate renewal requires local re-pairing. Do not expose raw EXR or enable remote service until these integration gates are tested. Never expose Nintendo services.

Next: host loopback integration with EXR/1 and real TLS, then devkitA64/OpenSSL feasibility and hardware smoke. No network endpoint is enabled by this PR.
